# 휴대폰 웹 푸시 운영 설정

공시한눈은 네이티브 앱 없이 브라우저의 Web Push API로 휴대폰 알림을 제공한다. 사용자가 알림센터에서 직접 허용한 기기에만 중요도 85점 이상의 핵심 공시를 전송한다.

## 적용 순서

1. `202609150001_add_web_push_notifications.sql`을 Supabase에 적용한다.
2. 한 번만 VAPID 키 쌍을 생성한다.

   ```bash
   pnpm exec web-push generate-vapid-keys --json
   ```

3. 다음 값을 GitHub Actions repository secret으로 등록한다.
   - `WEB_PUSH_VAPID_PUBLIC_KEY`
   - `WEB_PUSH_VAPID_PRIVATE_KEY`
4. 웹 애플리케이션 런타임에도 `WEB_PUSH_VAPID_PUBLIC_KEY`를 등록한다. 공개키이지만 환경별 교체를 위해 환경변수로 관리한다.
5. 배포 후 로그인한 실제 기기에서 알림센터의 `휴대폰 알림 받기`를 누른다.
6. Android Chrome과 iPhone 홈 화면 웹앱에서 수신 및 공시 상세 딥링크를 확인한다.

VAPID 개인키는 저장소, 로그, 클라이언트 번들에 넣지 않는다. 키를 교체하면 기존 브라우저 구독을 다시 받아야 한다.

## 전송 정책

- 휴대폰 푸시는 중요도 85점 이상만 전송한다.
- 기기 구독 이전에 생성된 공시는 소급 전송하지 않는다.
- 동일 인앱 알림과 동일 기기 조합은 한 번만 성공 처리한다.
- 일시 실패는 최대 3번 재시도한다.
- Push 서비스가 404 또는 410을 반환하면 만료된 기기 구독을 자동 비활성화한다.
- 푸시 전송 실패가 공시 수집 자체를 중단시키지는 않는다.

## 이메일 후속 작업

이메일은 웹 푸시 안정화 뒤 별도 채널로 추가한다. 로그인 이메일을 그대로 발송 대상으로 사용하되 반드시 별도 수신 동의를 저장한다. Gmail 또는 네이버 개인 SMTP 계정에 서비스가 종속되지 않도록 발송 제공자 인터페이스와 전송 기록을 분리한다.

후속 구현 항목:

- 사용자별 이메일 수신 동의와 해제
- 즉시 알림과 하루 요약 선택
- 이메일 인증 완료 계정만 발송
- 동일 공시의 채널별 중복 방지
- 반송, 스팸 신고, 발송 실패 처리
- Gmail·네이버 수신 테스트
